# 01 — Contracts

Every interface between components. **Work package WP-0** turns this document into machine-readable
contracts before any component is built:

- JSON Schemas → `shared/schemas/*.schema.json`
- OpenAPI 3.1 → `shared/openapi/{ingest,collector,agent,admin}.yaml`
- Python reference implementation → `shared/python/exp_common/`
- Fixtures → `test/fixtures/`

**Changing a contract after WP-0 needs a change request to the integrator.** No work package edits
`shared/` directly.

---

## 1. Conventions

| Item | Rule |
|---|---|
| Time | UTC ISO-8601 with ms and `Z` (`2026-11-18T20:00:00.123Z`). Timezone-aware input only; naive timestamps are rejected. Durations in `_ms` or `_s`. |
| IDs (user-facing) | Slugs `[a-z0-9][a-z0-9-]{0,63}`: `site`, `probe_id`, `collector_id`, `dashboard_id`, `runner_id`. Unique within the org. |
| IDs (internal) | Prefixed ULIDs: `h_` host, `cmp_` component, `rel_` release, `art_` artifact, `usr_` dashboard user, `noc_` NOC token, `drl_` drill, `run_` drill run, `evt_` audit event. ULID = 26 chars, Crockford base32, time-ordered. |
| Measurement IDs | ULID (no prefix), generated by the probe. |
| Secrets/tokens | 32 random bytes, base64url without padding, with a type prefix so scanners can spot them: `expe_` enrol token, `expa_` agent secret, `expi_` probe ingest token, `expd_` dashboard→collector API token, `expn_` NOC token. Stored server-side as `sha256(token)` hex unless noted. Compared in constant time. |
| JSON | UTF-8. Unknown fields: **ignored by readers** (forward compatibility), **never echoed** into labels or stored config. |
| HTTP errors | Body `{"error":{"code":"snake_case","message":"human text","details":{}}}` with the matching status. No stack traces, no secret values. |
| Lists | `{"items":[...],"next_cursor":"opaque-or-null"}`. `limit` ≤ 1000, default 100. |
| API versioning | Path prefix `/v1/`. Additive changes only within a major. |
| Schema versioning | Every document carries `"schema": "exp.<name>/<major>"`. |

## 2. Measurement — `exp.measurement/1`

Reference implementation: `shared/exp_schema.py` (moves to `shared/python/exp_common/schema.py` in
WP-0, same API). Human doc: `shared/SCHEMA.md`.

**Delta WP-0 MUST apply to the current reference implementation:**
1. Add **`id`** (string, ULID). `measure()` generates it. **Required at ingest.** Unique per probe;
   it is the dedupe key.
2. Add **`detail`** (object, optional): high-cardinality detail that never becomes a series label.
   Bounds: serialized ≤ 8 KiB, nesting depth ≤ 4, keys match `[A-Za-z_][A-Za-z0-9_]{0,63}`, string
   values ≤ 1,024 chars with no control characters, arrays ≤ 256 items.

Fields (after delta):

| Field | Type | Req | Notes |
|---|---|---|---|
| `schema` | `"exp.measurement/1"` | ✓ | |
| `id` | ULID | ✓ (ingest) | dedupe key |
| `ts` | ISO-8601 Z | ✓ | measurement start time |
| `probe` | slug | ✓ | must equal the ingest token's probe identity |
| `site` | slug | ✓ | must equal the probe's configured site |
| `test` | ident ≤ 64 | ✓ | see the catalog in §3 |
| `target` | string ≤ 256 | | becomes label `target` only if ≤ 80 chars |
| `outcome` | `ok\|degraded\|fail\|error` | ✓ | `error` = the probe could not run the test (not a network verdict) |
| `duration_ms` | number | | primary timing |
| `metrics` | map ident→finite number, ≤ 50 | | each one becomes a series `exp_<test>_<metric>` |
| `labels` | map ident→string ≤ 128, ≤ 20 | | low-cardinality only; reserved keys `probe`, `site`, `outcome`, `target`, `__*` |
| `detail` | object | | bounded, see above |
| `error` | string ≤ 512 | | short reason on `fail`/`error` |
| `agent_ver` | string | | probe version |

**Series mapping (VictoriaMetrics):** for each metric (and `duration_ms`):
`exp_<test>_<metric>{probe,site,outcome,<labels...>,target?}` at `ts`. Trusted labels (`probe`,
`site`, `outcome`) are applied last.

`degraded` when `total_ms` > 4×`apdex_t_ms` or `apdex` < 0.85; `path` is `degraded` when `mos` < 3.6;
`gateway` is `degraded` when `loss_pct` > 0 and < 50.

## 4. Ingest API (probe → collector)

`POST https://<collector>:8443/ingest/v1/measurements`

| Header | Value |
|---|---|
| `Authorization` | `Bearer expi_…` (per-probe ingest token) |
| `Content-Type` | `application/x-ndjson` (one measurement per line) |
| `Content-Encoding` | `gzip` (optional) |
| `User-Agent` | `exp-probe/<version>` |

**Limits:** ≤ 1,000 lines; ≤ 4 MiB on the wire; ≤ 16 MiB decompressed (stop reading beyond that
→ 413); each line ≤ 64 KiB.

**Processing order per batch:** authenticate the token → probe identity → for each line: parse →
`Measurement.validate()` → **identity binding** (`probe` = token identity, `site` = configured site)
→ time window check → dedupe on `(probe,id)` → store.

**Time window:** reject `ts` more than 60 s in the future (`ts_future`) or older than the record
retention (`ts_too_old`). Older-but-valid timestamps are normal (spool backfill).

**Response `200`:**
```json
{"accepted": 997, "duplicates": 2, "rejected": [{"line": 41, "id": "01JD…", "error": {"code": "identity_mismatch", "message": "probe 'x' does not match token identity"}}], "server_time": "2026-11-18T20:00:01.002Z"}
```

| Status | Meaning | Probe action |
|---|---|---|
| 200 | processed (per-line results) | delete accepted+duplicate+rejected lines from the spool; log rejects |
| 400 | not NDJSON, too many lines | log, split the batch, retry |
| 401 | missing/invalid token | stop pushing, report health `auth_failed`, retry every 60 s |
| 413 / 415 | too large / wrong type | split / fix |
| 429 | backpressure (`Retry-After: <s>`) | wait as told |
| 503 | collector unavailable | exponential backoff 1 s → 60 s with jitter |

The collector MUST accept and durably store to SQLite even when VictoriaMetrics is down, and
backfill VM when it recovers.

## 5. Collector query API (dashboard → collector)

Base `https://<collector>:8443/api/v1/`. Auth: `Authorization: Bearer expd_…` (per-dashboard token).
`X-Exp-User: <username>` is passed through for audit. `GET /healthz` is unauthenticated and returns
only `ok` or `fail`.

| Method & path | Query | Returns |
|---|---|---|
| `GET health` | — | `{status, version, vm:{up,lag_s}, ingest:{rps, rejects_1m}, probes:{total, reporting}, disk_free_mb}` |
| `GET probes` | `site?` | `{items:[{probe, site, label, last_seen, newest_s, version, state:"ok\|warn\|fail\|unknown"}]}` |
| `GET state` | `probe`, `at?` (default now), `voice?` (`plain\|sysadmin`) | **State** (below) |
| `GET states` | `site?`, `at?`, `voice?` | `{items:[State-lite: probe, site, severity, headline, lines:[{key,state}]]}` |
| `GET beats` | `probe`, `from`, `to` (≤ 6 h) | **Beats** (below) |
| `GET records` | `probe`, `test?`, `outcome?`, `from`, `to`, `limit?`, `cursor?` | `{items:[Measurement], next_cursor}` |
| `GET incidents` | `probe?`, `site?`, `from?`, `to?`, `open?` | `{items:[Incident]}` |
| `POST incidents/{id}/ack` | body `{note?}` | `204` (operator role, audited) |
| `GET summary` | `probe`, `minutes` (≤ 1440) | details tables: `{clients:[…], dhcp:[…], dns:[…], apps:[…], throughput:[…], servers:[…]}`; row shapes below |
| `GET query_range` | `query`, `start`, `end`, `step` | MetricsQL proxied to VM. Guards: only `exp_*` metric names; query ≤ 2 KiB; range ≤ 30 d; step ≥ 10 s; ≤ 500 series in the result (`422 too_many_series`, also when VM refuses; `422 result_too_large` above 32 MiB; `400 step_too_small` also above 11,000 points per series). `start`/`end` are RFC 3339 `…Z` or epoch seconds. |
| `GET stream` | `probes` (comma list) or `site` | SSE (below) |
| `GET drills/{run_id}` | — | drill report: `{run_id, type, target, start, until, phases[], expectation, observed:{ttd_s, ttr_s, lines_impacted[]}, result:"pass\|fail\|aborted"}` (M5) |
| `POST drills/{run_id}/abort` | — | `202` (operator role, audited) — LAN kill switch (M5) |
| `GET drills/control` | — (auth: executor's ingest token) | `{"abort":["run_id",…]}` — polled every 2 s by executors during active runs (M5) |

`POST incidents/{id}/ack` without an `X-Exp-User` header is `403 forbidden` (an unattributable acknowledgement
would defeat the audit trail); the operator role itself is checked by the dashboard session.

**Summary rows** (all keys always present, `null` when there is no data; consumers ignore unknown keys):
- `clients[]`: `port, dhcp_runs, dhcp_ok_pct, dhcp_total_p50_ms, dhcp_total_p95_ms, dns_runs, dns_ok_pct, dns_p50_ms, dns_p95_ms, apps_runs, apdex, worst_app, worst_apdex, wifi_ssid, wifi_rssi_dbm, flags[], no_link_runs`
- `dhcp[]`: `server, ports[], runs, ok_pct, offer_p50_ms, total_p50_ms, total_p95_ms, last_seen`
- `dns[]`: `resolver, kind, runs, ports[], p50_ms, p95_ms, fail_pct`
- `apps[]`: `app, apdex, runs, clients, p50_total_ms, p95_total_ms, ok_pct`
- `throughput[]`: `port, provider, down_mbps, up_mbps, latency_idle_ms, latency_loaded_ms, bufferbloat_ms, outcome, ts` (latest run per port and provider in the window)
- `servers[]`: `port, proto, requests, errors, p50_ms, sources[{client,count}], last_seen`

**State**
```json
{
  "schema": "exp.state/1",
  "probe": "probe-a1", "site": "hall-b", "at": "2026-11-18T20:06:00.000Z", "live": true, "newest_s": 3,
  "verdict": {

              "chain": [{"seg": "ports", "state": "ok"}, {"seg": "switch", "state": "ok"}, {"seg": "gateway", "state": "fail"},
                        {"seg": "edge", "state": "unknown"}, {"seg": "isp", "state": "unknown"}, {"seg": "dns", "state": "unknown"}, {"seg": "apps", "state": "unknown"}]}
  },
  "lines": [
    {"key": "network", "label": "Network", "state": "fail", "word": "unstable", "since": "2026-11-18T03:00:21.000Z",
     "detail": "10.1.0.1 not answering (12 of 12 ports)", "last_outage": null, "flaps": 0}
  ],
  "failing": [{"line": "network", "items": [{"text": "no reply from 10.1.0.1", "count": 12, "ports": ["c01", "c02"], "tests": ["gateway"]}]}]

```
`line.state ∈ ok|warn|fail|unknown`; `seg ∈ link, ports, switch, gateway, lan, edge, isp, wan, resolver,
dns_path, dns, apps, dhcp, ssid, wifi, path`.

**Beats**
```json
{"schema": "exp.beats/1", "probe": "probe-a1", "from": "...", "to": "...",
 "lines": {"network": [[1763496360000, 0], [1763496370000, 2]], "dns": [[1763496362000, 0]]},
 "markers": [{"t": 1763496380000, "kind": "incident|drill|ext", "text": "DNS down", "ref": "inc_…"}]}
```
Beat value: `0` ok, `1` warn, `2` fail, `3` unknown/probe error.

**Incident**
```json
{"id": "inc_01J…", "probe": "probe-a1", "site": "hall-b", "line": "dns", "kind": "down|again|flapping|back",
 "start": "…", "end": null, "where": {"seg": "edge", "ip": "10.1.0.2"}, "facts": ["No answers from 1.1.1.1 since 15:13:42"],
 "folded_into": null, "acked_by": null, "link": "https://<dashboard>/probe/probe-a1?at=…"}
```
`Incident.line` is a `line_key` **or `probe`**: the "probe silent" incident (no records for 90 s, 03 §6) is not about a
network line. `State` and `Beats` keep `line_key` only; dashboards render `probe` as "Probe". `kind` is `down|back`
(`again` after a re-failure) for it.

**SSE** (`text/event-stream`): events `beat` `{probe, line, t, v}`, `state` (State-lite),
`incident` (Incident). A `: keepalive` comment every 15 s. `retry: 3000`. A client may resume
with `Last-Event-ID`; the server replays ≤ 5 min. No initial state snapshot is sent on connect (clients read `GET states`
first); event ids are `<boot>.<n>`, and an id from before a collector restart replays nothing.

## 6. Agent API (agent → manager)

Base `https://<manager>/api/agent/v1/`. **Not** behind Cloudflare Access. Auth: `Authorization:
Bearer expa_…` except for `enrol`. Rate-limited per IP and per agent.

| Method & path | Request | Response |
|---|---|---|
| `POST enrol` | `{"token":"expe_…","facts":Facts}` | `201 {"agent_id":"h_…","agent_secret":"expa_…","poll_interval_s":30,"release_pubkey_pem":"…","manager_time":"…"}`; `401 invalid_token`, `410 token_used_or_expired`, `429` |
| `GET desired` | header `If-None-Match: "<etag>"` | `200` **Desired state** + `ETag`, or `304`; `404 not_found` while no desired state has been compiled for the host yet (the agent retries on the next poll, no back-off) |
| `GET releases/{version}/manifest` | — | the signed manifest JSON (bytes exactly as signed) |
| `GET releases/{version}/manifest.sig` | — | base64 Ed25519 signature |
| `GET artifacts/{artifact_id}` | — | artifact bytes (streamed from R2). `403` unless this artifact is referenced by this host's desired state. |
| `POST status` | **Status report** | `204` |
| `POST rotate` | `{}` (only when desired state carries a `rotate_agent_secret` action) | `200 {"agent_secret":"expa_…","grace_s":600}` — the old secret stays valid for `grace_s` |
| `POST decommissioned` | `{}` | `204` — the host's credentials are revoked |

`POST rotate` without a pending `rotate_agent_secret` action is `409 rotation_not_requested`.

`install.sh` is served at `GET https://<manager>/install.sh` (public, no secrets; template served with three
validated substitutions, see 06 §1). The one-time enrol token is given to `install.sh` as its positional argument
(`curl -fsSL https://<manager>/install.sh | sudo bash -s -- expe_…`) and sent only in the `POST enrol` body — never in a
URL, and the installed `exp-agent enrol` never receives it in argv (06 §8: `$EXP_ENROL_TOKEN` or stdin). The manager
origin used for SSO and links is the `MANAGER_URL` var (set by `deploy.sh`) or, until known, the origin of the first
authenticated admin request.

Compiled by the manager per host. The agent treats it as the whole truth for that host.

```json
  "site": {"id": "hall-b", "name": "Hall B", "timezone": "America/Chicago"},
  "agent": {"version": "0.1.0", "artifact": "art_01JD…", "poll_interval_s": 30, "status_interval_s": 60},
  "release": {"version": "0.1.0",
              "manifest_url": "/api/agent/v1/releases/0.1.0/manifest",
              "signature_url": "/api/agent/v1/releases/0.1.0/manifest.sig"},
  "components": [
    {"type": "collector", "id": "col-hallb", "component_id": "cmp_01JD…", "version": "0.1.0",
     "artifact": {"id": "art_…", "name": "exp-collector-0.1.0-amd64.tar.gz",
                  "url": "/api/agent/v1/artifacts/art_…", "sha256": "…", "size": 23456789},
     "config": { "...": "exp.collector.config/1 — see §9.2" },
     "creds": {"ingest_tokens.json": "{\"probe-a1\":\"<sha256>\"}",
               "dashboard_tokens.json": "{\"dash-main\":\"<sha256>\"}",
               "webhooks.json": "[{\"id\":\"wh_1\",\"format\":\"slack\",\"url\":\"https://hooks…\"}]"}},
    {"type": "probe", "id": "probe-a1", "component_id": "cmp_…", "version": "0.1.0",
     "artifact": {"…": "…"}, "config": { "...": "exp.probe.config/1" },
     "creds": {"ingest_token": "expi_…"}}
  ],
  "actions": [{"id": "act_01JD…", "type": "rotate_agent_secret"}],
  "decommission": false

```

Rules:
- `creds` values are strings written verbatim to `/etc/exp/<type>/creds/<name>` (root, `0600`)
  and exposed to the service with systemd `LoadCredential=`. They never appear in `config`, in
  logs, or in status reports.
- Component `type` ∈ `probe | collector | dashboard | runner | speedtest` (`speedtest` from M6,
  `12-speedtest-analytics.md` §7). Unknown types are ignored and reported.
- `actions` types: `rotate_agent_secret`, `restart_component` (`{component_id}`), `collect_diagnostics`
  (sanitized; no creds). No action executes arbitrary commands.
- `decommission: true` → remove all components, then call `POST decommissioned`, then remove the agent.
- The `ETag` is `"<host_id>:<version>"`.

`in_use_by` ∈ `mgmt | probe:<port_id> | none`. The manager uses `components[].facts.tls_fingerprint_sha256`
and `listen` to wire probes and dashboards to collectors.

**Host metrics** (collected by the agent): CPU from `/proc/stat` deltas, load from `/proc/loadavg`,
memory from `/proc/meminfo` (`used = total − available`), disks via `statvfs` for `/` and every
mount holding `/var/lib/exp` (deduplicated), disk I/O from `/proc/diskstats`, network from
`/sys/class/net/*/statistics` for **host-namespace** interfaces, uptime from `/proc/uptime`,
temperature from `/sys/class/thermal` when present. **Rates are deltas over the interval**; the
first report after a start has rates `null`. Counter resets (reboot, link reset) yield `null` for
that interval, never negative values.

**Process metrics** per component: summed over its units via systemd
(`systemctl show <unit> -p CPUUsageNSec -p MemoryCurrent -p NRestarts -p ActiveEnterTimestampMonotonic`).

### 8.1 Component health — `exp.health/1`

Every component implements `exp-<c> health --json` (exit 0 = process healthy; must answer in < 5 s; output
≤ 64 KiB). `status` carries severity: **`ok` and `degraded` exit 0, `fail` exits 1** (a component never exits 1 for
`degraded`; `degraded` means "serving, but something it depends on or reports on is wrong", e.g. the probe with the
collector unreachable while the spool accepts writes). The agent's reconcile health gate passes on `ok` or `degraded`
and fails on `fail`, a timeout, or unparsable output with a non-zero exit; `status: fail` with exit 0 is a
contradiction and counts as failing. Unknown `facts`/`metrics` keys are ignored by consumers (the probe adds
`shipper_state`, `tls_pin_mismatch`, `auth_failed`, `dropped_total`). The agent copies `status`, `detail`, `metrics`, and `facts` into the status report.
```json
{"schema": "exp.health/1", "status": "ok|degraded|fail", "detail": "", "version": "0.1.0",
 "uptime_s": 86000, "metrics": {}, "facts": {}}
```
Required metric keys (rates per second or per minute as named; counters since start where named `_total`):

| Type | `metrics` keys | `facts` keys |
|---|---|---|
| probe | `measurements_per_min`, `by_test_per_min` (map test → n), `fail_per_min`, `error_per_min`, `spool_depth`, `spool_bytes`, `push_lag_s`, `clock_offset_ms`, `skipped_per_hour`, `ports` (array, below) | `collector_reachable` (bool), `collector_url`, `mode` |
| collector | `ingest_records_per_s`, `ingest_rejected_per_min`, `ingest_duplicates_per_min`, `ingest_bytes_per_s`, `probes_total`, `probes_reporting`, `vm_up` (0/1), `vm_backlog_points`, `vm_series`, `vm_storage_gb`, `records_db_gb`, `storage_free_gb`, `days_to_full`, `sse_clients`, `open_incidents`, `webhook_failures_1h`, `rules_eval_ms_p95` | `tls_fingerprint_sha256`, `listen` |
| dashboard | `sessions_active`, `requests_per_min`, `sse_clients`, `collectors_total`, `collectors_reachable`, `login_failures_1h` | `tls_fingerprint_sha256`, `url` |
| runner | `drills_active`, `pullers` (array of `{source, last_ok, errors_1h}`); M6: `correlations_per_hour`, `evidence_lag_s_p95`, `syslog_lines_per_s`, `syslog_dropped_per_min` | `inventory` (discovered drill targets, bounded) |
| speedtest (M6) | `tests_per_hour`, `active_tests`, `queue_depth`, `internet_leg_paused` (0/1), `local_leg_gbps_p95`, `rejected_per_hour` | `url`, `tls_fingerprint_sha256` |

Probe `ports[]` item: `{"id","iface","role","link":"up|down","leased":true,"ip","gateway","rx_pps","tx_pps",
"rx_bps","tx_bps","rx_errors","tx_errors","rx_drops","tx_drops","last":{"network":"ok","dhcp":"ok","dns":"fail"}}` —
counters read inside each port's namespace (the agent cannot see them).
`days_to_full` = free storage ÷ the 24-h average growth rate (`null` when growth ≤ 0).

## 10. Releases and artifacts

**Artifact name:** `exp-<component>-<version>-<arch>.tar.gz`, with `component` ∈ `agent, probe,
collector, dashboard, runner` and `arch` ∈ `amd64, arm64, noarch`. Pure-Python components are
`noarch`. The collector is per-arch because it bundles VictoriaMetrics.

**Tarball layout** (top directory `exp-<component>-<version>/`):
```

```

```json
{"schema": "exp.manifest/1", "version": "0.1.0", "created": "…", "min_agent_version": "0.1.0",
 "artifacts": [{"name": "exp-probe-0.1.0-noarch.tar.gz", "component": "probe", "arch": "noarch", "sha256": "…", "size": 812345}],
```

Every unit with creds uses `LoadCredential=` and the agent guarantees each referenced file exists
(possibly empty) — a missing credential file stops a unit from starting (EXM lesson).

**Credential refresh = restart.** systemd copies a `LoadCredential=` file into `$CREDENTIALS_DIRECTORY` only when the
unit (re)starts. Whenever a unit's credential files change, the agent therefore **restarts that unit** (token rotation
would otherwise leave the OLD token valid); it never relies on reload or `SIGHUP` for credentials. `ExecReload=` may
still serve config-only reloads a component implements. Components may additionally poll their credentials directory
(collector: every ≤ 10 s; dashboard: every 5 s) so dev/test layouts and mirrors work without a restart.

**Collector state layout.** `exp-collector.service` uses `StateDirectory=exp/collector`, so `/var/lib/exp/collector/`
is owned by `exp-collector` (SQLite WAL needs `-wal`/`-shm` next to `records.db`, mode `0600`). Before the first start
the agent (root, never following symlinks) prepares `tls/` (`exp-collector` `0700`, `key.pem` `0600`, `cert.pem` `0644`;
the collector refuses a key readable by "other") and `vm/` (`exp-vm` `0700`; VM size/series come from VM's loopback
HTTP API). **Launch wrappers:** `exp-victoriametrics.service` runs `exp-collector vm-exec --config … --state-dir …`
and `exp-iperf3.service` runs `exp-collector iperf3-exec`; they validate the config and `execv` the vendored
`victoria-metrics` / `iperf3` with an argv list (no shell, no env file, no word splitting), so config values are never
interpolated into unit files. The flags are exactly those of 03 §1 (`exp-collector vm-args` prints them); `iperf3` binds
the collector mgmt IP and the configured port (default 5201) and exits 0 when disabled. `vendor/victoria-metrics` is
shipped sha256-pinned.

**Dashboard runtime paths** come from the systemd environment (`STATE_DIRECTORY`, `RUNTIME_DIRECTORY`,
`CREDENTIALS_DIRECTORY`; units use `StateDirectory=exp/dashboard`, `RuntimeDirectory=exp/dashboard`), not from
`exp.dashboard.config/1`; its `health --json` talks to the service over `@RUN@/health.sock`.

## 12. SSO handoff token (manager → dashboard)

JWT, HS256, secret = the dashboard's `sso_secret`.
Claims: `iss` = `exp-manager:<org>`, `aud` = `<dashboard_id>`, `sub` = admin email, `name`,
`role` ∈ `viewer|operator|admin`, `iat`, `exp` = `iat + 120`, `jti` (UUID).
Delivery: the manager returns an auto-submitting HTML form that **POSTs** `token` to
`https://<dashboard>/auth/sso` (never in a URL). The dashboard verifies the signature in constant
time, `aud`, `iss`, `exp`/`iat` (±60 s skew), and that `jti` is unused (cache 10 min), then sets a
session cookie (`Secure; HttpOnly; SameSite=Lax`, `session_hours`).
